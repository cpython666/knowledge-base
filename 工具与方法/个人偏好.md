# 个人偏好

## GitHub 项目参考

GitHub 项目的 Star 数量是我的重要参考，介绍、推荐或对比 GitHub 项目时，请一并列出查询时的 Star 数量。

## 协作与交付

1. 代码按功能分批提交，用中文按 `<type>(<scope>): <subject>` 写提交说明，并汇总交付结果。
2. 已确认且可复用的项目经验，请及时整理进对应项目的 skill。
3. 标题、风格和视觉方案先给候选，等我选定后再制作。
4. 请用简体中文回复，包括过程说明和最终结果。
5. 合并时保留双方有效改动、妥善解决冲突，不覆盖未提交内容。
6. 需要我复制或转交的提示词，请尽量用简短直接的说法。

## Git 提交格式

来源：[Git笔记](https://cpython666.github.io/backend/git)

提交信息格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

常用 type：feat（新功能）、fix（修复）、docs（文档）、style（格式）、refactor（重构）、perf（性能）、test（测试）、chore（构建或依赖）、revert（恢复先前提交）。

标题用祈使语气（如「修复登录页面Bug」，不要写成「修复了登录页面Bug」），首字母小写，不超过 50 个字符，结尾不加句号。正文解释「是什么」和「为什么」，每行不超过 72 个字符。破坏性变更在页脚以 `BREAKING CHANGE:` 开头；关闭 issue 使用 `Closes #123`。

示例：

```
feat(用户管理): 添加用户登录功能

增加了用户使用邮箱和密码登录的功能。
该功能包含前端和后端的实现。

BREAKING CHANGE: 登录接口现在需要认证。
Closes #45
```
